# 背景

随着安全对抗的日益升级，在进行 native 层逆向分析时，我们经常会遇到目标 so 文件中的字符串被加密的情况。由于字符串是定位关键代码的重要手段，因此对加密字符串进行解密还原显得尤为重要。本文将介绍几种常见的字符串加密破解方法，并结合实际案例进行讲解。

# 追踪所有返回的字符串

某些字符串混淆方案会在运行时调用字符串解密函数，将解密后的字符串以 C 指针的形式返回给调用者。然而，这些解密函数可能较难快速定位。因此，我们可以通过 Frida 对模块中的所有函数进行 hook，在函数返回时使用 readCString() 尝试输出结果。

优点：

1. 如果运气好，可以直接看到一些敏感的关键字符串，从而快速定位关键函数。

缺点：

1. 可能导致 APP 崩溃，追踪过程不够稳定。
2. 输出数据较多，有效信息难以筛选。

具体流程：

1. 运行脚本 toolchain_collect_ret_insn.py 。
2. 选择“是”：在 IDB 所在目录生成对所有函数的 ret 指令处进行 hook 的脚本。
3. 选择“否”：仅生成导出函数的 ret 指令处的 hook 脚本。
 ![image](https://bbs.kanxue.com/upload/attach/202507/719252_85XQJSAE5SA8UHR.webp)
4. 对生成的脚本进行简单调整后即可使用。

# 定位高频调用函数

思路
某些字符串混淆方案会在运行时频繁调用固定的字符串解密函数。由于一个 so 文件通常包含数百甚至上千个字符串，这些解密函数的调用次数往往远高于普通功能函数。通过统计所有函数的交叉引用次数并按从高到低排序，可以快速定位这些字符串解密函数。此外，这种方法还可以用于定位字符串的构造函数，作为去混淆的关键点。

优点
稳定性较高，只需针对少量函数进行 hook。
干扰数据较少。
适用于基于堆和基于栈的字符串加密方案。

缺点：
需要手动排查并定位字符串解密函数。

使用方法：
运行脚本 top_xrefs.py，输入需要查看的调用次数最多的 N 个函数。

# trace Jni 的字符串相关函数

思路：
在 native 层通过 Java 传递字符串参数或返回 Java 类型的字符串时，通常会调用 NewString、NewStringUTF、GetStringUTFChars 等 JNI 接口。我们可以通过 hook 这些接口来追踪字符串。

优点：

1. 产生的无关数据较少。

缺点：

1. 输出数据量较少，通常难以定位关键函数。

# 内存dump

思路：
某些 so 文件使用开源的 OLLVM 进行字符串加密，其特点是在 init 函数中将字符串解密回 data 段。我们可以通过 Frida dump 工具直接从内存中提取解密后的字符串。

优点：

1. 对于字符串回填到 data 段的保护方式，能够高效去混淆。

缺点：

1. 无法处理基于堆或栈的字符串加密。

具体流程：

1. 启动 APP，触发关键逻辑，确保目标模块加载到内存。
2. 使用 Frida dump 工具从内存中提取解密后的 so 文件。
3. 将 fix_convey_str_list.py 脚本拷贝到 IDA 插件目录，重启 IDA 生效。
4. 在 IDA 中加载 dump 的 so 文件，使用插件导出解析的字符串列表。
 ![image](https://bbs.kanxue.com/upload/attach/202507/719252_DZ8CJR5YYS5FH38.webp)
5. 导出字符串列表后，将其重新导入非 dump 的 so 文件中进行分析。
 ![image](https://bbs.kanxue.com/upload/attach/202507/719252_2P3VHM29QJMJCXY.webp)

# 内存扫描

思路：
针对基于堆的字符串加密方案，动态申请内存保存解密后的字符串，并将字符串指针保存在全局变量中。我们可以编写 IDA 脚本扫描 data 和 bss 段的内存空间，尝试读取字符串指针并输出解密后的字符串。

优点：

1. 对动态分配内存的字符串加密方案效果显著。

缺点：

1. 无法处理基于栈的字符串加密。

具体流程：

1. 使用 toolchain_trace_dyn_dec_str.py 脚本生成 Frida js 脚本，修改 Module.findBaseAddress 中的模块名。
2. 启动 APP，触发关键逻辑，等待字符串解密后frida加载脚本进行 dump。

 ![image](https://bbs.kanxue.com/upload/attach/202507/719252_XRQGRC7N3U9MC7Y.webp)

1. 保存 dump 的字符串信息到文件中，使用 IDA 脚本 toolchain_trace_dyn_dec_str.py 补充信息回到 IDB 文件中。
 ![image](https://bbs.kanxue.com/upload/attach/202507/719252_ZJXB7QX9347B7H6.webp)

由于有的地址是bss段的，没有在文件中分配实际的空间，因此不能直接 patch 对应地址的内容。 我这里的解决思路是在对应地址下个断点，并添加一个注释，这样通过断点窗口就可以方便的进行 字符串查找了…… Ctrl+ALT+B 打开断点界面，右击选择Columns仅展示 comment（同样Ctrl+F搜索字符串即可）：
 ![image](https://bbs.kanxue.com/upload/attach/202507/719252_4ZNHQ8MNZDW35CM.webp)

在汇编窗口上可以看到字符串备注：

# 总结

本文围绕 native 层字符串加密的逆向破解方法展开，结合实际案例详细介绍了多种应对策略，包括追踪返回字符串、定位高频调用函数、JNI 字符串追踪、内存 dump 和内存扫描等技术手段。通过这些方法，可以有效应对不同类型的字符串加密方案，为逆向分析提供强有力的支持。希望本文的分享能为读者在实际工作中提供启发和帮助。

| 字符串加密方式 | 应对思路 |
|-|-|
| 调用字符串解密函数解密明文到堆栈上 | 1. 使用 top xref 定位高频调用函数并 hook；2. 追踪所有返回的字符串；3. trace JNI 字符串相关函数 |
| 回填解密后的明文到 data 段 | 使用 Frida dump 提取字符串后重新 patch 回原始 IDB |
| 动态分配内存进行解密，保存字符串指针到 bss、data 段 | 扫描 bss、data 段的指针，尝试读取字符串，并回填 IDB |
| 内联解密指令并在栈上解密 | 暂无通用解决方案，可尝试使用 Unicorn 模拟执行，但实现较复杂。 |
