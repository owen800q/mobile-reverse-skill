# 适配修复

## 修复思路

1、加固的逻辑一般不会变，所以之前脱壳脚本的流程也不用动。

2、每次编译后so中的函数地址可能会发生变化，所以脚本中调用的函数地址不能写死，需要脚本根据so进行自动适配

3、分析so找出特征码，对引用的地址进行定位

## 适配点

通过查看之前的脚本，找出所有需要适配的地方

| 0x2B604 | 获取密钥 |

## 适配-获取密钥

原脚本中的地址是0x2B604，在ida中找到这个函数，没有发现能够定位的地方

![image](https://bbs.kanxue.com/upload/attach/202302/2PXFQ3V4FVD8SPZ.jpg)

于是查看一下引用，发现0x29BC0调用了这个函数，

0x29BC0使用了一些常量字符串，并且0x29BC0这个函数没有被混淆，所以引用字符串的时候，代码偏移是不会变的

![image](https://bbs.kanxue.com/upload/attach/202302/AXYQ4DKYXNFFQ8W.jpg)

于是决定通过"PROCESS_CHILD"这个字符串进行定位，先找到引用的时候偏移为+0x98的函数

![image](https://bbs.kanxue.com/upload/attach/202302/C2N4NPERAVR97TA.jpg)

然后查看汇编代码，往上倒回去找，找到的第一条BL指令，跳转的地址就是我们需要的地址

![image](https://bbs.kanxue.com/upload/attach/202302/97VZX6HSFTJ3FEY.jpg)

添加脚本代码

```
def find_func_0():
    ea = idc.find_binary(0, idc.SEARCH_DOWN, '50 52 4F 43 45 53 53 5F  43 48 49 4C 44 00')
    for ref in idautils.DataRefsTo(ea):
        s = idc.get_func_off_str(ref)
        if s and s.endswith('+98'):
            ea = ref
            break

    while True:
        ea = idc.prev_head(ea)
        if idc.print_insn_mnem(ea) == 'BL':
            return idc.get_operand_value(ea, 0)
```

## 适配-上下文地址

原脚本中的地址是0x368E4，在ida中查看这个地址的引用，发现有几百处，其中一处和字符串常量"libshell-superx.2019.so"挨得比较近。

![image](https://bbs.kanxue.com/upload/attach/202302/H8MXVN3REYEWPDZ.jpg)

于是决定通过这个字符串进行定位，先找到引用的时候偏移为+0x72的函数

![image](https://bbs.kanxue.com/upload/attach/202302/8FE9NQ2355BJQFT.jpg)

然后查看汇编代码，往上倒回去找，找到BLX strncpy指令之后的LDR指令，计算出我们需要的地址

![image](https://bbs.kanxue.com/upload/attach/202302/2RJXA5HNBK47W7D.jpg)

添加脚本代码

```
def find_ctx():
    ea = idc.find_binary(0, idc.SEARCH_DOWN, '6C 69 62 73 68 65 6C 6C 2D 73  75 70 65 72 78 2E 32 30 31 39 2E 73 6F')
    for ref in idautils.DataRefsTo(ea):
        s = idc.get_func_off_str(ref)
        if s and s.endswith('+72'):
            ea = ref
            break

    while True:
        ea = idc.prev_head(ea)
        # BLX             strncpy
        if idc.print_insn_mnem(ea) == 'BLX' and idc.print_operand(ea, 0) == 'strncpy':
            break

    ldr = idc.next_head(ea)
    r0 = idc.get_wide_dword(idc.get_operand_value(ldr, 1))
    pc = idc.next_head(ldr)
    pc = pc / 2 * 2 + 2 * 2
    return idc.get_wide_dword(r0 + pc)
```

## 适配-系统函数

这些函数的查找方式都是一样的。

以calloc为例，原脚本中的地址是0x1D48，

在ida中查看，发现该地址在.plt段，并且引用了符号"__imp_calloc"

因此我们只需要把这些系统函数的名字找出来，通过查找符号引用就可以找到他们的地址

![image](https://bbs.kanxue.com/upload/attach/202302/DDR63E4BWSEXNT4.jpg)

添加脚本代码

```
func_start_set = {0}
func_name_list = ['__imp_calloc', '__imp___aeabi_memclr8', '__imp___aeabi_memclr', '__imp___aeabi_memclr4',
                  '__imp___aeabi_memcpy', '__imp_strcpy', '__imp_getpid', '__imp_open', '__imp_read', '__imp_close',
                  '__imp_free', '__imp_malloc', '__imp_puts', '__imp_printf']
func_map = {}

def find_sys_func():
    plt_start = idc.get_segm_by_sel(idc.selector_by_name('.plt'))
    plt_end = idc.get_segm_end(plt_start)
    for func in func_name_list:
        extern_func = idc.get_name_ea_simple(func)
        for ref in idautils.CodeRefsTo(extern_func, 1):
            if plt_start <= ref < plt_end:
                func_start = idc.get_func_attr(ref, idc.FUNCATTR_START)
                func_start_set.add(func_start)
                func_map[func] = func_start
                break
```

## 修复checksum

通过查看dex文件格式可知，checksum是dex+8处的4字节，使用Alder32算法计算的dex文件+12之后部分的校验和。

添加脚本代码

```
crc = zlib.adler32(bytes(dex_mem[12:])) & 0xffffffff
for i in range(4):
    dex_mem[8 + i] = crc & 0xff
    crc >>= 8
```

重新运行脚本，得到修复后的dex，成功反编译
