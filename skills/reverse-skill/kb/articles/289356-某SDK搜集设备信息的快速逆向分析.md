对某 app逆向分析时，协议中携带一个设备相关的token，跟踪后发现这个token是极验sdk提供的token。

![image](https://bbs.kanxue.com/upload/attach/202512/770147_5BUATFPZNJCZRUQ.webp)

通过getData函数返回的数据，上报后台，后台返回数据中提供了token数据。

token是由后台返回，所以无法分析它是一个什么数据，可能是一串设备环境数据，或者只是一个设备id数据。但是这都不重要，重要的是它上报给后台什么数据。

**native层逆向**

native层是 libgtcore.so，拖进IDA中反编译，没有发现getData函数。hook registerNatives后打印绑定的native层函数偏移：

![image](https://bbs.kanxue.com/upload/attach/202512/770147_BT7Y297HKKKVW8U.webp)

找到了，位于模块偏移 0x553c4 和 0x55438。代码中主要调用的是第二个，我们主要分析 0x55438处的函数。

![image](https://bbs.kanxue.com/upload/attach/202512/770147_Q64XDZM8XQWJ4GJ.webp)

我将这个函数重命名成了 getDataWithConfig，这个函数比较简短，可以明显看出 v6就是最最终返回的字符串。这个字符串由函数 0x5281c返回。

反编译片段：

![image](https://bbs.kanxue.com/upload/attach/202512/770147_PZ7FRQY2HYTYRVC.webp)

很明显这是一个平坦化混淆后的函数，v3变量在衔接原始的分支。我们不用关心原始的函数分支结构是怎样的，只用看最终的解密值是怎么生成的。

找到函数的返回语句：

![image](https://bbs.kanxue.com/upload/attach/202512/770147_CFW2K3VCJCBGQ5X.webp)

这个函数最终返回了v20，往上找，v20在什么地方出现，点击时会高亮显示。

![image](https://bbs.kanxue.com/upload/attach/202512/770147_JSGM5SBS6BW6S6Z.webp)

上述两个地方对v20进行了赋值，上面一个赋值了空指针，想必v1才是需要分析的值。当v3 = 5668920时，才会走到这里，我们点击5668920，看看哪里会高亮显示：

有两处：

第一处：

![image](https://bbs.kanxue.com/upload/attach/202512/770147_H4SMYHTY54PUXFR.webp)

第二处

![image](https://bbs.kanxue.com/upload/attach/202512/770147_FQ879SHK2XC9BKK.webp)

第二处将v1赋值成了空指针，走的应该是错误的分支。第一处将v1赋值成了v45，v45[v47] = 0，看起来就像是对字符串的最后一个字节截断，v47对应字符串长度。因此第一处像是正确分支。那么继续向前定位 -325650688高亮的地方：

发现了：

![image](https://bbs.kanxue.com/upload/attach/202512/770147_7SK656Q53KHQGGP.webp)

一般情况下，函数返回 0 对应着函数执行正常，因此上述base64_encode函数执行正确后，才会走后续正确的返回分支。通过frida打印该函数的参数，才发现这是一个base64编码函数，v45是输出字符串，v47是输出字符串长度。v42是输入数据。

v3 = -1972881541才会执行到这里，继续跟踪高亮：

![image](https://bbs.kanxue.com/upload/attach/202512/770147_Q379V4TH2N3FS4A.webp)

v42是后面base64编码的输入数据，v45是后面base64编码的输出数据，这里很明显是对输入数据进一步赋值，并申请内存，用于保存输出数据。

v42的前5个字节看起来是固定值，其中前3个字节从 0x117410拷贝，后两个字节赋值成了 0 和 5 ，看起来像是版本。然后是16个字节，可能是加密的key，后面跟着4个字节，熟悉数据加密的人一看就知道是原始数据长度了。最后拼接了长度为v39的v36数据，这个应该就是加密后的数据。

跟踪v36的赋值来源，有两处：

![image](https://bbs.kanxue.com/upload/attach/202512/770147_FPW4G5AUTNS4HM3.webp)

和

![image](https://bbs.kanxue.com/upload/attach/202512/770147_HR88XBW5XUUWBXQ.webp)

这两处都是调用 0xf62dc函数，因此需要重点分析这个函数。

frida 打印参数

\```
Interceptor.attach(base.add(0xf62dc), {
    onEnter: function (args) {
      console.log(args[2].toInt32());
      console.log(Memory.readByteArray(args[3], 32));
      console.log(args[4].readUtf8String());
      this.output = args[5];
    },
    onLeave: function (retval) {
      console.log(Memory.readByteArray(this.output, 32));
    },
  });
\```

通过输出参数，就可以明显看出来这是一个加密函数，参数5传递了原始数据

![image](https://bbs.kanxue.com/upload/attach/202512/770147_JP8PKPXW5GGQD4N.webp)
