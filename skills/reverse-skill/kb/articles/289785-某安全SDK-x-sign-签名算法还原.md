# 某安全SDK x-sign 签名算法还原

## 基于ARM64汇编Trace的逆向分析

通过对某安全SDK的ARM64执行日志（Trace）进行深度分析，完整还原签名算法流程。本文重点介绍从汇编指令中扣取算法的分析方法。

## 0. VM字节码解释器结构

从汇编日志提取的VM结构：

## 2. 核心算法

### 使用的加密原语

1. **MD5** (初始化常量已确认)

	- `0x67452301`
	- `0xefcdab89`
	- `0x98badcfe`
	- `0x10325476`
2. **SHA1** (轮常量已确认)

	- `0x5a827999` (轮0-19)
	- `0x6ed9eba1` (轮20-39)
	- `0x8f1bbcdc` (轮40-59)
	- `0xca62c1d6` (轮60-79)
3. **XOR混淆**

	- 输入字符串每8字节与 `0x2626262626262626` 进行XOR
	- 结果再与 `0xFFFFFFFFFFFFFFFF` 进行XOR (取反)
4. **自定义Base64编码**

## 4. 汇编分析流程

### 4.1 识别VM调度循环

在trace日志中搜索重复出现的指令模式，定位VM主循环：

```
; VM Dispatch Loop (出现频率极高)
L102100: ldrh w5, [x21, #0x10]!      ; PC += 16, 读取opcode
L102101: ldr x4, [x23, x5, lsl #3]   ; handler = table[opcode * 8]
L102102: br x4                        ; 跳转到handler
```

**分析要点：**

- `x21` 每次递增 `0x10`，说明每条VM指令占16字节
- `x23` 指向handler表，通过 `lsl #3` (乘8) 索引，说明每个表项是64位指针
- 统计 `br x4` 后的跳转地址，可枚举所有handler

### 4.2 Handler功能识别

通过handler内部的指令特征识别功能：

**示例1：识别XOR Handler (Opcode 0x274)**

```
L102135: ldr x16, [x25, #0x40]   ; 读取VM寄存器[8]
L102136: ldr x13, [x25, #0x48]   ; 读取VM寄存器[9] = 0x2626262626262626
L102137: eor x17, x16, x13       ; result = reg[8] XOR reg[9]
L102138: str x17, [x25, #0x50]   ; 写回VM寄存器[10]
```

**示例2：识别NOT Handler (Opcode 0x272)**

```
L102148: ldr x1, [x25, #0x50]    ; 读取上一步XOR结果
L102149: mov x5, #0xffffffffffffffff
L102150: eor x2, x1, x5          ; result = value XOR 0xFFFF... (取反)
L102151: str x2, [x25, #0x58]    ; 写回
```

### 4.3 通过魔数定位加密算法

**MD5识别 - 搜索初始化常量：**

```
; 在trace中搜索 0x67452301
L12468961: mov w8, #0x2301
L12468962: movk w8, #0x6745, lsl #16  ; w8 = 0x67452301 (MD5 A)
L12468970: mov w9, #0xab89
L12468971: movk w9, #0xefcd, lsl #16  ; w9 = 0xefcdab89 (MD5 B)
```

**SHA1识别 - 搜索轮常量：**

```
; 搜索 0x5a827999 定位SHA1
L16501050: mov w10, #0x7999
L16501051: movk w10, #0x5a82, lsl #16 ; K0 = 0x5a827999 (轮0-19)
...
L16502000: mov w10, #0xeba1
L16502001: movk w10, #0x6ed9, lsl #16 ; K1 = 0x6ed9eba1 (轮20-39)
```

### 4.4 数据流追踪

从输入到输出追踪数据变换：

| 1234567891011121314151617181920 | `[输入字符串]``↓` `↓  L102135``-``L102150: XOR` `+` `NOT 变换``↓  观察: 每``8``字节与` `0x2626``... XOR，再取反``↓``[XOR变换后数据]``↓``↓  L12468961``-``L12469182: MD5压缩``↓  特征:` `64``轮运算，``4``个``32``位状态变量``↓``[MD5哈希` `16``字节]``↓``↓  L16501050``-``L16501180: SHA1``-``HMAC``↓  特征:` `80``轮运算，``5``个``32``位状态变量``↓``[HMAC签名` `20``字节 ×` `3``]``↓``↓  组装``76``字节结构``↓``[Base64编码输出]` |
|-|-|

### 4.5 SHA1轮函数还原

从trace中提取SHA1单轮计算的关键指令：

```
; ROL(a, 5) 实现
L16501180: lsl w15, w14, #5      ; 左移5位
L16501181: lsr w16, w14, #27     ; 右移27位
L16501182: orr w17, w15, w16     ; 合并 = 循环左移5

; ROL(b, 30) 实现
L16501193: lsl w15, w14, #30     ; 左移30位 (0x1e)
L16501207: lsr w16, w14, #2      ; 右移2位
L16501235: orr w17, w15, w16     ; 合并 = 循环左移30

; 轮函数 f(b,c,d) - 根据轮次不同
; 轮0-19:  (b & c) | (~b & d)     Ch函数
; 轮20-39: b ^ c ^ d              Parity函数
; 轮40-59: (b & c) | (b & d) | (c & d)  Maj函数
; 轮60-79: b ^ c ^ d              Parity函数

; 最终加法
L16501280: add w8, w8, w17       ; temp = ROL(a,5) + f + e + K + W
```

### 4.6 定位关键常量

通过在trace中批量搜索，提取算法使用的所有常量：

| 常量值 | 出现位置 | 用途 |
|-|-|-|
| `0x2626262626262626` | L102136 | XOR混淆密钥 |
| `0xFFFFFFFFFFFFFFFF` | L102149 | NOT运算 |
| `0x67452301` | L12468961 | MD5初始值A |
| `0xefcdab89` | L12468970 | MD5初始值B |
| `0x98badcfe` | L12468980 | MD5初始值C |
| `0x10325476` | L12468990 | MD5初始值D |
| `0x5a827999` | L16501050 | SHA1 K0 |
| `0x6ed9eba1` | L16502000 | SHA1 K1 |
| `0x8f1bbcdc` | L16503000 | SHA1 K2 |
| `0xca62c1d6` | L16504000 | SHA1 K3 |

### 4.7 输出结构分析

在trace末尾追踪最终输出的组装过程：

```
; 写入版本号
L20001000: mov w8, #0x366b
L20001001: strh w8, [x0]         ; offset 0: version

; 写入类型
L20001010: mov w8, #0x0801
L20001011: strh w8, [x0, #2]     ; offset 2: type

; 写入时间戳
L20001020: str w9, [x0, #4]      ; offset 4: timestamp (从参数获取)

; 写入标志位
L20001030: mov w8, #0xb447
L20001031: movk w8, #0x0082, lsl #16
L20001032: str w8, [x0, #8]      ; offset 8: flags

; 复制HMAC结果 (20字节 × 3)
L20001040: ; memcpy到offset 12, 32, 52
```

---

### 结构验证

- 头部 `6b36`
- 类型 `0108`
- 时间戳为小端序Unix时间戳
- 三个20字节块符合SHA1
- 末尾4字节校验
