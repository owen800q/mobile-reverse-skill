## 一、解码原理

经过 DSL 描述以后，引擎不会直接解析 DSL，而是会预先生成一张静态查找表。查找表中的每一个节点都会转换成 `(mask, value)` 的形式，运行时只需要进行按位与和比较即可完成匹配，因此解码过程不需要解释 DSL，也不需要字符串匹配。

还是以这个**C4.1.92 Data Processing – Immediate**里面的**add**为例，在解码的时候会为这棵树生成**mask**和**value**

指令查表的逻辑就是 ：

| 1 | `(instruction & mask) == value` |
|-|-|

C4.1.92 Data Processing – Immediate：xxx100xxxxxxxxxxxxxxxxxxxxxxxxxx的mask和value分别是：

     mask: 469762048，二进制：00011100000000000000000000000000

     value: 268435456,  二进制：00010000000000000000000000000000

C4.1.92.3 Add/subtract (immediate): xxx100010xxxxxxxxxxxxxxxxxxxxxxx的mask和value分别是：

     mask：528482304，二进制：00011111100000000000000000000000

     value：285212672，二进制：00010001000000000000000000000000

ADD <Wd|WSP>, <Wn|WSP>, #<imm>{, <shift>} 指令的mask和value分别是：

     mask：4286578688，二进制：11111111100000000000000000000000

     value：285212672，二进制：00010001000000000000000000000000

###

拿一条add指令举例：

\```
11003108 add w8, w8, #12
\```

那么伪代码的逻辑就是这样的：

\```
// 第一步uint64_t instruction = 0x11003108;if((instruction & 469762048) == 268435456) // match C4.1.92 Data Processing – Immediate  if ((instruction & 528482304) == 285212672) // match C4.1.92.3 Add/subtract (immediate)    if ((instruction & 4286578688) == 285212672) // match ADD <Wd|WSP>, <Wn|WSP>, #<imm>{, <shift>}
\```

## 二、操作数提取

以add指令的操作数为例：

\```
ops_desc: [  { t: :r_w, v: '0:5', wsp: true },   { t: :r_w, v: '5:5', wsp: true },   { t: :imm, v: '10:12', shift: { t: :lsl, v: 'f:f1' } }],
\```

1. 第一个操作数是从0开始，5位
2. 第二个操作数是从5开始，5位
3. 第三个操作数是从10开始，12位，这个操作数有shift，shift的逻辑就是f:f1
4. 这里的f:f1表示一个函数，也就是父节点上的fshift，fshift里面就是一个字符串描述的函数，直接可以求出shift的值即可

这里还是以

| 1 | `11003108 add w8, w8, #12` |
|-|-|

为例

指令的二进制是：0001000100000000001100 01000 01000

第一个操作数0:5 -> 01000 -> 8 -> 寄存器是16位w -> w8

第二个操作数5:5 -> 01000 -> 8 -> 寄存器是16位w -> w8

第三个操作数10:12 -> 000000001100 -> 12 -> 常数 #12， shift查表根据函数计算0

得到的结果就是add w8, w8, #12

\```
            fshift: {                return (_lrs_eq(c, 22, 1, 0x0) ? 0 : 12);            },            falias_add_mov_boolean: {                // sh == '0' && imm12 == '000000000000' && (Rd == '11111' || Rn == '11111')              return _lrs_eq(c, 22, 1, 0x0) && _lrs_eq(c, 10, 12, 0x0) && (_lrs_eq(c, 0, 5, 0x1f) || _lrs_eq(c, 5, 5, 0x1f));            }            // 这是两个函数传入的就是instruction的code，即c
\```

## 三、引擎实现

描述指令的DSL完成后，那么就可以实现一个generator了，这个generator其实是生成具体语言的数据的作用，可以用它来生成c/c++/golang/rust等等数据结构，我用c写的引擎，那么它就应该给我生成c语言的代码，我的c的结构设计如下：

有了这个结构，generator就可以用生成一个巨大的c的指令码表

根据指令码表，就可以循环也好，递归也好的去查表解析具体的指令了。
