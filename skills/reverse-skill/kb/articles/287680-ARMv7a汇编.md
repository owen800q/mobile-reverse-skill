## 一、寄存器

| 通用寄存器（32-bit） | 别名/过程调用规范中作用 |
|-|-|
| R0-R3 | 参数传递/结果返回（调用者保存） |
| R4-R8 | （被调用者保存） |
| R9 | 平台寄存器（可变用途） |
| R10 | （被调用者保存） |
| R11 | FP，栈帧指针寄存器，记录当前栈帧基址 （被调用者保存） |
| R12 | IP，内部过程调用临时寄存器 |
| R13 | SP，栈指针，指向栈顶，任何函数的出入口处，需满足8字节对齐，即SP mod 8 = 0，即SP mod 0x08 = 0 |
| R14 | LR，链接寄存器，保存函数返回地址 |
| R15 | PC，程序计数器 |
| 其他寄存器 |  |
| CPSR | 当前程序状态寄存器，重点位：N（负数）、Z（零）、C（进位）、V（溢出）、T（处理器指令集，如thumb、arm） ![image](https://bbs.kanxue.com/upload/attach/202507/PUUCP39MC8FM7SG.jpg) |

总结：

1、15个通用32位寄存器

2、R4-R11，被调用者保存。即，子函数被调用时，需保存这些寄存器的值，在返回父函数时，恢复这些寄存器的值。R9比较特殊，保留平台相关的配置，有时候有用有时候不用，可直接按被调用者保存处理。

3、R11，FP栈帧指针。一般指向调用函数的FP，形成调用链，可用于栈回溯。实际使用中最常用是用来寻址栈中的数据，因为SP会频繁改变，但FP不会

4、R12，IP寄存器，常用来寻址外部导入函数。比如调用printf，会用来计算printf的地址。

5、LR，不是非易变寄存器，被调用者可以改变，而不恢复，只需要在返回调用者的时候，将LR POP到PC就行。所以可以把LR保存到堆栈，最后从堆栈 POP 到PC

6、CPSR，T标志位控制处理器指令集，如T32（thumb模式）或者A32（arm模式）。A32为定长4字节指令，T32为2字节或4字节指令。NZCV条件标志位

其他（不多BB了解不多）：

系统寄存器

浮点寄存器（SX为32个单精度（32-bit）寄存器，DX为16个双精度（64-bit）寄存器），S0-S15参数传递/调用者保存，S16-S31被调用者保存。D0-D7双精度参数传递，D8-D15双精度，被调用者保存。

1、A32（arm模式）和T32（thumb模式），A32定长4字节指令，T32为2字节指令与4字节指令混合。

2、数据处理指令，同样的运算方式，一般会有三种指令变体。如下面三条指令，执行的都是加法运算：

ADD（只存放结果，不影响标志位）

ADDS（既存放结果，又影响标志位）

CMN（只影响标志位，不存放结果）

同理，还有SUB、SUBS、CMP；AND、TST；EOR（TEQ）

3、由于A32指令定长4字节，所以无法容纳32位立即数，一般会使用立即数扩展。

```plain
MOV R0,0x12345  (该指令不合法，立即数20位，MOV指令立即数只有12位)
```

MOV指令立即数扩展：A32ExpandImm，imm12，将12位立即数扩展为32位，运算过程是后8位循环右移前4位的值*2

```plain
MOV R0,0xC60000  (合法，立即数24位，但是指令编码中可用12位表示为0x0008000000C6，即0xC6循环右移0x0008*2=16位，可得0x00C60000)
```

或者使用

```bash
MOV R0,0x5678
MOVT R0,0x1234
```

可得到：R0 = 0x12345678

4、ADR、ADRL

```plain
ADR Rd,#imm  (相当于ADD Rd,PC,#imm)
```

ADR一般用于寻址计算，实现PC偏移寻址。

如下图main函数调用libc中printf函数。

![image](https://bbs.kanxue.com/upload/attach/202507/UMSDG7499ZQ3RUZ.jpg)

![image](https://bbs.kanxue.com/upload/attach/202507/JW2ZZ7W2JZZ37DE.jpg)

（off_1654 - 0x1508）可看作printf存储地址与PC之间的偏移offset，ADR指令将PC加上，得到printf的地址。加载前后，offset是不变的，PC加载前0x508加载后变为实际运行时候的指令地址0xB6FF8508，使得通过PC寻址的printf的地址发生改变为0xB6FF9654，如此寻到的printf地址才是正确的地址。

![image](https://bbs.kanxue.com/upload/attach/202507/BTRC42A8FVQQD92.jpg)

R12之前说过，常用来寻址外部导入函数。如printf函数的调用，由于arm和thumb的BL指令无法寻址完整的32位地址空间，如无法BL 0x12345678，此处则通过ADR、LDR指令来计算地址并加载到PC实现跳转。这段代码通常称为veneer，特点是，一般不改变除r12寄存器和状态寄存器之外的寄存器。

RSB R0,R1,#8  =>  R0=8-R1

BIC R0,R1,#8  =>  清除R1的第3位，结果存入R0

6、访存：

```plain
LDR R0,[R1,#4]！  ([R1+4]=>R0，R1=R1+4)，！代表需要回写基址寄存器
```

将偏移量与从基址寄存器获取的地址相加，结果作为内存访问的地址，并回写到基址寄存器R1。

```plain
LDR R0,[R1],#4  ([R1]=>R0，然后R1=R1+4)
```

从基址寄存器获取的地址，不做任何修改，作为内存访问的地址。将偏移量与该地址相加，然后回写到基址寄存器R1。

```plain
STR R0,[SP,#-4]!  （把R0压栈）
LDR R0,[SP],#4    （出栈到R0，对应上面一句）
```

注意：Arm是满减栈。如下图假如是一个栈帧结构。

“满”意味着SP指针总指向栈顶最后一个元素，图中是0x222，SP的值即位0x00000ff8。

“减“意味着栈的生长方向是向内存地址减小的方向。当放入一个元素，会往低地址放。如STR R0,[SP,#-4]!，则会将R0的值存入SP-4的位置即0x0000ff4处，然后将SP-4写回SP。

![image](https://bbs.kanxue.com/upload/attach/202507/MRN6RDJW3W3ABJV.jpg)

7、块访存：
LDMFD、STMFD、LDMIA、STMIA

|  | IA | IB | DA | DB |
|-|-|-|-|-|
| STM | 快速复制内存 |  |  | 相当于STMFD |
| LDM | 相当于LDMFD |  |  |  |

FD：full descending     IA：increase after     DB：decrease before

栈操作：

当SP为操作寄存器时，STMFD = STMDB，LDMFD = LDMIA

STMFD SP!,{R3-R7,LR} = PUSH，从右到左压栈，LR压栈、R7压栈...、R3压栈【小标号对应低地址，大标号对应高地址】

LDMFD SP!,{R3-R7,PC} = POP，从左到右出栈，栈顶出栈到R3、...、出栈到R7、出栈到PC

快速复制内存：

先LDMIA、再STMIA

8、分支和模式切换：

B、BL、BLX、BX、MOV PC,Rd、LDR PC,[Rd]、CBZ、CBNZ

B：常用FEFFFFEA，后24位FFFFFE立即数-2，-2 * 4 +8 = 0，即跳转到自己

|  | imm | Rm |
|-|-|-|
| BL | 操作1 | - |
| BX | 操作2 | 操作3 |
| BLX | - | 操作1、操作3 |

操作1：返回地址 ORR 当前T标志位 =>写入LR

操作2：0x1 => 写入T标志位

操作3：Rm & 0x1 => 写入T标志位，Rm & 0xFFFFFFFE => 写入 PC

MOV PC,Rd，也能实现跳转，不能改变指令集模式，写入PC奇数值会异常

LDR PC,[Rd]，能根据reg最后一位改变指令集模式

10、不多BB了解不多：

系统调用 (`SVC`): 是用户程序请求内核服务的机制。它通过触发软件中断异常，使 CPU 切换到特权模式 (SVC)，让内核代码代为执行需要特权的操作。

协处理器操作 (`MRC`/`MCR`/`CDP` 等): 是在特权模式下直接控制和访问硬件扩展功能（如 MMU, Cache, FPU） 的手段。它们是内核实现许多系统调用功能（尤其是与内存管理、缓存一致性、浮点运算相关的）所依赖的底层硬件指令。

11、PC的读写

IDA伪指令：=()相当于PC偏移取值，如

```plain
LDR R0,=0xE92D0090  (相当于LDR R0,[PC,#imm]，此处R0=0xE92D0090)
```

读PC：A32（arm）读PC+8，T32（thumb）读PC+4 。A32是定长4字节指令，T32是2字节指令或4字节指令。

```plain
MOV PC,R0
LDR R0,[PC]
```

在调试中：

arm：LDR R0,[PC,#-4]，该指令读下一条指令（因为读PC会读出PC+8，然后-4就是下一条）。但是如果在调试中，不管下一条指令是什么，都会读出E7F001F0（UND），说明被IDA调试，涉及到IDA调试原理，即在当前指令更改下一条指令为E7F001F0，抛出异常，由IDA捕获后加载原指令。此特性可用于反调试
